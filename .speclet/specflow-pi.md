# SpecFlow Pi Package

## Requirements
As a pi user running the SpecFlow workflow, I want a live cockpit panel and in-terminal document review, so that I always know which phase each spec is in, when the agent is waiting on my approval, and can read requirements/design/tasks without leaving the terminal.

### Acceptance Criteria
- AC1: WHEN an interactive session starts with eligible specs under `.specflow/`, THE SYSTEM SHALL show a panel with the selected spec's name, inferred phase (1–4 of Requirements/Design/Tasks/Execution, `Archived` for archived status, Done for completed), done/total task count, frontmatter status, and — when present — an orthogonal "awaiting your review" gate badge. The task count is rendered only when `tasks.md` declares at least one task (requirements-only and metadata-only specs show the phase rail without a `0/0` count), and a flat spec whose status metadata is missing or invalid renders its status as `unknown` (legacy specs still infer from the containing directory) and ranks alongside in-progress entries. Automatic selection ranks gate-paused first, then in-progress, completed, archived; ties use newest mtime. Selection pinned via `/specflow` persists while the spec exists; with no pin, ranking reapplies each refresh. IF `.specflow/` is absent or has no eligible specs, THE SYSTEM SHALL hide the panel.
- AC2: WHEN the SpecFlow skill stops for document or task review (including every Phase 4 per-task stop), IT SHALL record `gate: review` in the spec's `tasks.md` frontmatter (creating a metadata-only `tasks.md` when none exists, matching the early-archive precedent) and clear the field when approval is received and work resumes. WHEN a session resumes a spec whose recorded gate no longer matches actual pending state, IT SHALL reconcile the field (clear it when no review is pending). The rule lives in the SKILL.md Core Contract (always loaded) and the Resume section of `references/lifecycle-phase.md`; `review` is the only defined value, and the extension renders nothing for absent or unknown values.
- AC3: WHEN `/specflow` runs interactively, THE SYSTEM SHALL list all discovered specs as `name · status · done/total · gate?` (the count segment omitted when `tasks.md` declares no tasks) and offer switching the panel selection and opening a document; IF there are no eligible specs, THE SYSTEM SHALL report "No specflows found." In non-interactive mode it SHALL return the same listing as text and never open dialogs.
- AC4: WHEN a document is opened from `/specflow` (requirements.md, design.md, tasks.md, or project.md), THE SYSTEM SHALL render it as themed markdown inside a bordered, scrollable popup closable with `escape`/`q`; IF the file is missing or unreadable, THE SYSTEM SHALL show an error notification naming the file and not open the popup.
- AC5: WHEN discovering specs, THE SYSTEM SHALL treat as eligible every directory under `.specflow/` containing any of `requirements.md`, `design.md`, or `tasks.md` — covering the flat `specs/{feature}/` layout and the legacy `specs/active|completed|archived/` layout — taking frontmatter status as authoritative and inferring status from the containing directory for legacy specs without it. Read/parse failures SHALL neither crash pi nor stop subsequent refreshes, and the extension SHALL never write to `.specflow/` (gate writes belong to the skill/agent).
- AC6: WHEN an eligible file or directory is created, edited, atomically replaced, or deleted during an interactive session, THE SYSTEM SHALL reflect the settled disk state within 1 second under normal local filesystem operation, and session shutdown SHALL stop all refresh work.
- AC7: WHEN `npm pack --dry-run` runs in `specflow-pi/`, THE SYSTEM SHALL include only the package manifest, README, LICENSE, `skills/specflow/**`, `extensions/index.ts`, and `src/**`. IF the bundled skill tree differs from the source `specflow/` tree (SKILL.md, `references/**`, `templates/**` — missing, extra, or changed files, checked in both directions), THE SYSTEM SHALL fail the prepublish check with a non-zero exit naming the drifted path, while its copy mode makes the trees byte-identical (pruning dest files absent from source). Extension code SHALL follow an explicit source→dest mapping: `src/shared.ts` is a verbatim byte-guarded copy of `speclet-tui/src/shared.ts`, while `extensions/index.ts`, `src/controller.ts`, `src/render.ts`, and `src/parse.ts` are declared forks (initially copied from speclet-tui, thereafter owned by this package with recorded divergence intent); the guard SHALL fail when `src/shared.ts` drifts from its counterpart, and the forked `extensions/index.ts` SHALL NOT register any keyboard shortcut (the speclet task inspector and its `shift+up` binding are dropped, so coexistence with speclet-tui raises no command or shortcut conflict).
- AC8: WHEN `bun test` runs in `specflow-pi/`, THE SYSTEM SHALL pass; and when the package is installed via `pi install -l <abs-path>` into a scratch project, THE SYSTEM SHALL register the specflow skill and the TUI extension (panel, `/specflow` picker, document viewer) without errors — including coexistence with speclet-tui loaded in the same session — carrying the `pi-package` keyword and `*`-range optional peer dependencies on `@earendil-works/pi-coding-agent` / `@earendil-works/pi-tui`.

## Design Notes
- New package `specflow-pi/` in this repo, mirroring the proven speclet-pi structure: `package.json` (`@abianbiya/specflow`, name verified free 2026-09-09, `0.1.0`, MIT, `pi: { extensions: ["./extensions"], skills: ["./skills"] }`, `files` allow-list, `prepublishOnly`), `extensions/index.ts` + `src/` (extension code), `skills/specflow/` (full skill copy), README, LICENSE.
- Skill bundling is whole-directory: `scripts/sync-skill.ts` copies the entire `../specflow/` tree (SKILL.md, `references/**` including lifecycle-phase.md, `templates/**` including project.md — the latter is linked from `references/project-setup.md`) into `skills/specflow/`; `--check` compares both directions (missing or extra dest files are drift) and exits non-zero naming the drifted path (AC7); copy mode prunes dest files absent from source (N2: a renamed reference must never linger). specflow/ has cross-linked references and templates, so partial sync would ship broken links.
- Extension code fork map (F1): `src/shared.ts` holds the five import-free generic primitives — `stripControlSequences` (its home is `speclet.ts`, not `render.ts`), `visibleLen`, `padVisible` (private helpers used by `wrapText` and `renderDetailsLines`), `wrapText`, `renderScrollbar` — and is a verbatim byte-guarded copy of `speclet-tui/src/shared.ts`, enforced by `scripts/check-fork.ts` (both prepublish checks run: `sync-skill.ts --check && check-fork.ts`). Each package keeps its own `StyleKind`/`Styler`/`plainStyler`: speclet's kinds are task-shaped (`taskDone`, `openGlyph`) and specflow's are phase-shaped (`phase`, `gate`), so hoisting them would make byte-identity impossible. Task 2's extraction keeps the 87-test speclet baseline untouched via re-export shims: `render.ts` re-exports `wrapText`/`renderScrollbar`, `speclet.ts` re-exports `stripControlSequences`. `extensions/index.ts`, `src/controller.ts`, `src/render.ts`, `src/parse.ts` — forks from speclet-tui (`parse.ts` from `speclet.ts`), owned by this package from the fork onward; their divergence is intentional and the mapping table in `check-fork.ts` records it. The forked `extensions/index.ts` drops the speclet task inspector (user-excluded) and with it the `shift+up` registration (`speclet-tui/index.ts:318-353`), so the two extensions cannot conflict. The speclet-pi counterpart guard is a separate follow-up (scratchpad), out of scope here — after this extraction it must also copy `shared.ts` and keep speclet-pi's `speclet.ts` re-export.
- Gate signal (AC2): extend the source skill in `specflow/` — Core Contract sentence (always loaded, so it governs every gate including pre-lifecycle stops) plus a `gate` row in the lifecycle metadata table in `references/lifecycle-phase.md` — instructing the agent to set `gate: review` when stopping for any review, including every Phase 4 per-task stop (F3: truthful per-stop gating), and clear it on approval-to-resume; the Resume section of `references/lifecycle-phase.md` gains the reconciliation rule for gates left by interrupted sessions (F2). `review` is the only defined value. Then sync into the package.
- Phase inference (AC1): eligible dir with only requirements.md → Phase 1; +design.md → Phase 2; +tasks.md with tasks → Phase 3 (Tasks) while its gate is set, Phase 4 (Executing) once cleared; `status: completed` → Done; `archived` → Archived label. The gate badge (F3) is orthogonal to the phase label and never replaces it — during execution the badge flips per task stop by design. Known ambiguity (revising an approved planning doc): gate-cleared + tasks-present shows the conservative Executing label while the popup shows the authoritative document; upgrade path: a skill-written `phase:` field later.
- Reuse from speclet-tui: per the fork map above — shared primitives live in byte-guarded `shared.ts`; picker plumbing, poll-controller pattern, border/scrollbar/markdown popup rendering, and the interactive-mode discriminator/textual fallback path are forked and adapted. New: multi-file spec discovery, phase/gate model, panel content (heading + phase rail line), document-viewer popup over the four files.
- Panel budget: ≤ 6 content lines (heading, phase rail, progress line) — smaller than speclet's 12 since no task rows. Same interactive-mode discriminator and textual fallback path as speclet-tui.
- ponytail: skipped — archive/reason browsing, deviation-log views, task inspector (user-excluded), live popup refresh (snapshot at open), explicit `phase:` field, CI/gallery media. Upgrade path noted above.

**Independent review round (completed).** pi-glm reviewed the manager's half against AC1/AC3/AC4/AC6/AC7/AC8 and falsified nothing: all 7 verification claims came back CONFIRMED, and it added robustness checks (symlinked dirs/documents skipped at every level, so no traversal loop or double-count; two concurrent 500 ms polls harmless). It raised 5 findings, all reproduced and fixed before finalizing:

| # | Severity | Finding | Fix |
|---|----------|---------|-----|
| F1 | Medium | `parse.ts` set `name: basename(dir)` unstripped; the panel heading and popup header render it raw, so a directory name carrying ANSI/control sequences could corrupt the widget (only `listText`/`pickerOptions` stripped) | strip once at the source in `parseSpecDir`, plus a `parse.test.ts` case proving `evil␛[31mname` → `evilname` |
| F2 | Low-Med | Two specs sharing a basename (flat + legacy, or under different intermediate dirs) produced identical picker labels, and the lifecycle skill requires resolving duplicates "using actual paths" — the duplicate became unpinnable and could open the wrong spec's document | `displayNames()` in `render.ts` appends the shortest unique parent-path chain to *colliding* labels only (`panel (specs)` vs `panel (archived)`); unique names stay undecorated. Regression tests for both layouts and for deeper collisions |
| F3 | Low | `render.ts` re-implemented `visibleLen`/`padVisible` although `./shared.js` exports both — two implementations of one primitive can drift | import them from `./shared.js` |
| F4 | Low | A partial discovery failure (`dirError` from one unreadable subdirectory) made the non-interactive branch print the error *instead of* the listing, hiding the specs that did resolve | print diagnostic and listing together |
| F5 | Low | No size/binary guard: a multi-MB or binary document was fully read and handed to the markdown renderer (render lag; replacement chars) | `lstat` size cap (512 kB) and NUL sniffing in `openDocumentPopup`, each reporting the file name and opening nothing |
| F6 | Info | AC7's "no keyboard shortcut" clause was enforced by review only | `check-fork.ts` now scans `extensions/index.ts` for `pi.registerShortcut` and exits non-zero naming the line; verified by injecting one |
